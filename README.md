# Generic Test Fixture (GTF)

A reusable, modular endurance-cycling rig: an Arduino Opta WiFi drives a
StepperOnline CL57RS closed-loop stepper over Modbus RTU (RS-485), with a
3-colour stack light on a Waveshare Modbus relay module. Test programmes are
generated by an AI from a structured interrogation, against a controlled
specification and a known-good reference implementation.

## How to make a new programme

Give your AI of choice these three items:

- `docs/CONOPS.md` — the specification (GTF-CONOPS-001)
- `skill/grill-the-user.skill` — the interrogation skill (bundles the
  reference implementation)
- or, unpacked: `skill/grill-the-user/SKILL.md` +
  `skill/grill-the-user/references/reference-implementation.ino`

Then tell it: **"I want to make a new programme"**. It should interrogate you
topic by topic, show a confirmation table, and only then generate a sketch —
adapted from the reference implementation, never written from scratch.

## Repository map

| Path | What it is |
|---|---|
| `docs/CONOPS.md` | The authoritative spec. Its revision table (§14) is the project changelog — currently Rev L. |
| `skill/grill-the-user/` | Skill source: interrogation instructions + the known-good reference implementation. **Single source of truth for the reference sketch.** |
| `skill/grill-the-user.skill` | The packaged skill bundle (a zip). Regenerate after editing the source: `cd skill && zip -r grill-the-user.skill grill-the-user/SKILL.md grill-the-user/references/reference-implementation.ino` |
| `programmes/` | Generated, confirmed test programmes. One folder per sketch (Arduino IDE requirement). Current: 135° oscillation, 23 rpm, 9,000 cycles. |
| `commissioning/` | Hardware bring-up tools: relay-board and motor commissioning sketches, one-time address/baud provisioning tools, and the commissioning procedure. Not production logic. |
| `tools/RS485_Direct_Test.html` | Browser-based raw Modbus RTU tester (Web Serial, Chrome/Edge). Talks to the bus via a USB-RS485 adapter with no installed software — the tool that settles "is it the code or the hardware" arguments. |

## Hardware snapshot (details in the ConOps)

- Bus: RS-485, Modbus RTU, **9600 8N1** — locked to the relay module's only
  power-cycle-safe baud (see COM-02/COM-06 for why)
- CL57RS drive: slave **ID 1** (DIP-switched, core hardware)
- Waveshare Relay 4CH: slave **ID 2** (software-set, persistence verified);
  stack light Green/Amber/Red on channels 1/2/3
- Panel: Start/Pause/Stop on Opta I3/I4/I5, E-stop two-channel (DI1 hardware
  + I1 software)

## Rules that exist because they were learned the hard way

The ConOps Appendix A is binding on any AI generating code for this fixture:
permitted-API whitelist, FC 0x0F ban on the relay module, `coilWrite()` plain
0/1 only, `RS485.setDelays()` before `ModbusRTUClient.begin()`, and the
pre-emit checklist. Each rule traces to a commissioning failure documented in
the revision table.
